==== Konfigurationsänderungen für Oracle und Microsoft SQL Server in der Well-Architected-Analyse

Im Rahmen der gut strukturierten Analyse wurden mehrere Datenbankkonfigurationen kombiniert und in die folgenden Konfigurationen umbenannt.

* *Speicherplatzmanagement*: umfasst Speicherplatzreservierung, Speicherplatzzuweisung und Teilreserve
* *Speichereffizienzen*: umfasst Komprimierung, Deduplizierung und Verdichtung
* *Tiering/TCO-Optimierung*: umfasst die Tiering-Richtlinie und die Mindestkühltage für das Tiering
* *Lokale Snapshots planen*: beinhaltet Snapshot-Richtlinie


link:https://docs.netapp.com/us-en/workload-databases/optimize-overview.html["Konfigurationsanalyse in Workload Factory"]

Die Berechtigungen für Datenbanken wurden aktualisiert, um den Funktionszugriff zu verbessern und den SSM-Zugriff dort einzuschränken, wo er nicht erforderlich ist.

Die Berechtigungen für Operationen und Fehlerbehebung ermöglichen Änderungen an Ihren Ressourcen, die Analyse von Fehlerprotokollen, eine umfassende Well-Architected-Analyse Ihrer Ressourcen sowie die Behebung von Konfigurationsproblemen.

==== Benutzerdefinierte Dashboards



===== Benachrichtigungen für benutzerdefinierte Dashboards

Workload Factory benachrichtigt Sie jetzt, wenn Ihr benutzerdefiniertes Dashboard bereit ist oder wenn die Erstellung fehlschlägt.

Nachdem Sie ein benutzerdefiniertes Dashboard erstellt haben, erhalten Sie eine Benachrichtigung mit einem direkten Link zur Anzeige. Wenn die Erstellung fehlschlägt, wird eine Benachrichtigung mit einem Link zum benutzerdefinierten Dashboard-Inventar bereitgestellt, um es erneut zu versuchen.

Dies hilft Ihnen zu erkennen, wann Ihr Dashboard bereit ist, und erleichtert die Überprüfung oder Neuerstellung.

link:https://docs.netapp.com/us-en/workload-setup-admin/create-custom-dashboard.html["Informationen zur Erstellung benutzerdefinierter Dashboards"]

link:https://docs.netapp.com/us-en/workload-setup-admin/configure-notifications.html["Informationen zur Konfiguration von Benachrichtigungen"]



===== Private und öffentliche benutzerdefinierte Dashboards

Benutzerdefinierte Dashboards enthalten jetzt Freigabeeinstellungen. Ein Dashboard kann privat gehalten oder mit dem Team geteilt werden.

Neue Dashboards sind standardmäßig privat und nur für Sie sichtbar. Ein Dashboard kann jederzeit öffentlich gemacht werden, sodass es mit allen in Ihrem Workload Factory Konto geteilt werden kann.

Jede Dashboard-Karte zeigt ein Label „Privat“ oder „Öffentlich“, sodass schnell ersichtlich ist, welche Dashboards freigegeben sind.

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-custom-dashboards.html#view-and-share-dashboards["Informationen zur Sichtbarkeit und Freigabe von Dashboards"]

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-custom-dashboards.html#change-dashboard-visibility["Informationen zum Teilen von Dashboards"]



==== Verwaltung von KI-Funktionen

Mit den folgenden Einstellungen in der Workload Factory Administration lässt sich der Zugriff auf KI-Funktionen in Ihrer gesamten Organisation steuern.

* NetApp-verwaltetes Bedrock verwenden (empfohlen und standardmäßig aktiviert, mit monatlichen Kreditlimits)
* Alle KI-Funktionen deaktivieren


Die neue Administrationsseite ermöglicht die Verwaltung dieser Einstellungen an einem Ort.

Zu den KI-Funktionen gehören Ask Me, benutzerdefinierte Dashboards, Rule Builder, und Analysetools für EMS, Datenbankprotokolle und Volume-Latenz.

Wenn die KI-Funktionen deaktiviert sind, sehen die Benutzer eine Meldung, dass die KI nicht verfügbar ist.

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["Informationen zur Verwaltung von KI-Funktionen"]



[[eda-workloads]]
=== EDA-Workloads



==== KI-Latenzanalyse mit Kostenkontrollen

Als Administrator der Workload Factory kann der Zugriff auf die KI-Latenzanalyse in der gesamten Organisation gesteuert werden.

* *NetApp-verwaltete KI-Guthaben*: Wenn Ihr Administrator dies aktiviert, kann die KI-Analyse über die von NetApp verwaltete Amazon Bedrock Integration genutzt werden. Es ist keine zusätzliche Einrichtung erforderlich. Die monatliche Nutzung ist durch das zugewiesene Budget begrenzt. Wird das monatliche Limit erreicht, sind KI-gestützte Funktionen deaktiviert und eine entsprechende Meldung wird angezeigt.
* *Vom Administrator deaktiviert*: Wenn Ihr Administrator die KI-Funktionen deaktiviert, werden die Optionen für die KI-Analyse ausgegraut und Sie sehen eine Meldung, dass die Funktion deaktiviert ist.




==== Management der elastischen Durchsatzerhöhung

Sie können nun das Verhalten bei der Erhöhung des Durchsatzes auf der EDA-Übersichtsseite für ein oder mehrere ausgewählte FSx for ONTAP Dateisysteme verwalten.

* *Modusauswahl*: *Automatisieren* oder *Empfehlen* auswählen.
* *Massenaktualisierungen*: Ein oder mehrere Dateisysteme können ausgewählt und Modus- sowie Parameteränderungen in einem Schritt angewendet werden.
* *Dialog zur Durchsatzverwaltung ändern*: Die Einstellungen zur Durchsatzsteigerung mit den EDA-Standardwerten lassen sich im Dialog bearbeiten.
* *Erweiterte Einstellungen*: Zusätzliche Durchsatz-Entscheidungsparameter können in einem erweiterbaren Abschnitt *Erweiterte Konfiguration* konfiguriert werden.
* *Tabellensichtbarkeit*: In der Tabelle „Cluster“ ist eine neue Spalte *Durchsatzmanagement* verfügbar, die über die Spalteneinstellungen aktiviert werden kann.
* *Konfiguration der oberen Karte*: Die obere Karte unterstützt jetzt die Konfiguration des Durchsatzsteigerungsmodus, ähnlich wie bei der SSD-Verwaltung.


link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html["Informationen zur Verwendung des Overview Dashboards"^].

=== Amazon FSX für NetApp ONTAP



==== Neues, gut strukturiertes Dashboard für alle FSx for ONTAP Systeme verfügbar.

Die Well-Architected-Analyse ist jetzt für FSx for ONTAP Dateisysteme über das neue Well-Architected-Dashboard in NetApp Workload Factory verfügbar. Das neue Dashboard bietet eine zentrale Übersicht über alle Ihre Dateisysteme in allen Konten und Regionen sowie deren Konfigurationen an einem Ort. Eine Popup-Benachrichtigung erscheint, wenn der *Well-architected*-Tab von einem Dateisystem aus aufgerufen wird. Das neue Dashboard ist über die Auswahl von *Well-architected* im linken Navigationsmenü in Workload Factory zugänglich.

Der Zugriff auf die Well-Architected-Analyse für ein bestimmtes Dateisystem sowie über die Menüoption *Well-architected* im Storage ist weiterhin möglich.



==== Neue Widgets wurden dem Storage Dashboard hinzugefügt.

Das Storage Dashboard enthält jetzt zwei neue Widgets, die Ihnen helfen, Ihre Speichernutzung zu verstehen und Optimierungsmöglichkeiten zu finden.

* *Die am häufigsten erkannten Workloads* Zeigt Workload-Daten an, die vom Tagging-Dienst in Ihrer Umgebung gefunden wurden. Workloads mit einem Konfidenzwert über 80 %, die zugehörige FSx-Ressourcen wie Volumes und Blockgeräte enthalten, werden angezeigt. Jeder Workload zeigt seinen Namen, die Anzahl der Ressourcen, die bereitgestellte Kapazität und die genutzte Kapazität. Eine Sortierung nach Ressourcenanzahl (Standard), bereitgestellter Kapazität oder genutzter Kapazität ermöglicht eine schnelle Identifikation der größten Workloads und ein Verständnis der Speichernutzungsmuster.
* *KI-gestützte Erkenntnisse und Beobachtungen* Zeigt KI-generierte Erkenntnisse zu Ihren verwalteten Assets. Das Widget analysiert Ihre Bestandsdaten im ausgewählten Bereich und hebt die drei wichtigsten Ergebnisse in Schlüsselbereichen hervor, darunter Kapazität, Leistung, Datenschutz, Replikation, Kosteneinsparungen und Speichertrends.


Jede Erkenntnis umfasst eine Zusammenfassung, detaillierte Ergebnisse und empfohlene Maßnahmen. Durch das Erweitern einer Erkenntnis werden weitere Details angezeigt, und Probleme können nach Schweregrad, Leistungsverbesserungen und Kosteneinsparungspotenzialen priorisiert werden.



==== Arbeitslastkennzeichnung



===== AWS Systems Manager Integration für die Workload-Kennzeichnung

Der Workload Tagging Service arbeitet jetzt mit AWS Systems Manager zusammen, um Host-Inventardaten detailliertere Informationen hinzuzufügen. Workload Factory kann nun SSM-Inventarinformationen erfassen und verarbeiten, um Workloads besser zu identifizieren und zu klassifizieren. AWS SSM Attribute werden ebenfalls in den Tagging-Prozess einbezogen, um die Genauigkeit der Workload-Erkennung zu verbessern.

Jede volumebezogene Konfiguration im Well-Architected Dashboard enthält nun die Spalte *Workload* in der Ressourcentabelle. Diese Spalte zeigt die Workload, die Workload Factory jedem Volume zuordnet.



==== Workload Tagging und KI-Funktionen

Workloads werden nicht getaggt, wenn ein Administrator KI-Funktionen deaktiviert. Wenn KI-Funktionen in den Workload Factory-Kontoeinstellungen deaktiviert sind, identifiziert oder klassifiziert der Tagging-Dienst keine Workloads auf Ihren Speicherressourcen.

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["Informationen zur KI-Administration"^].



==== Verbesserung der Berechnung der Einsparungen im Snapshot erkunden

Explore Savings verwendet jetzt eine konsistente Snapshot-Kapazitätsberechnung, sodass die Einsparungsschätzungen von FSx for ONTAP den zusätzlichen Bedarf an Snapshot-Kapazitätspool korrekt berücksichtigen.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/explore-savings.html["Einsparmöglichkeiten für Ihre Speicherumgebungen auf Amazon Elastic Block Store, FSx for Windows File Server und Elastic File System."]



===== Replikationsverzögerungsdaten in eine CSV-Datei exportieren

Sie können nun Replikationsverzögerungsdaten in eine CSV-Datei exportieren, um die Daten in einer Tabellenkalkulation zu analysieren und sie mit anderen zu teilen.



==== S3 Zugriffspunktereignisse

Sie können nun S3 Access Point-Ereignisse nach einem festgelegten Zeitplan an das SNS Topic senden. Jede Aktualisierung enthält alle Ereignisse, die seit der letzten Aktualisierung aufgetreten sind.

Um Benachrichtigungen für S3-Ereignisse einzurichten, link:https://docs.netapp.com/us-en/workload-fsx-ontap/edit-s3-access-points.html["S3 Zugriffspunkte bearbeiten"] und unter dem Abschnitt *Journaltabelle* *S3-Ereignisse per SNS senden* auswählen.

==== Volumes Explorer

Der Volumes Explorer bietet eine einfache, durchsuchbare Ansicht aller Volumes in NetApp Workload Factory. Es wird schnell ersichtlich, welche Volumes Block- oder Dateiworkloads bereitstellen. Die logische Größe, die physisch genutzte Kapazität und die Nutzung von Speichereffizienzfunktionen (Komprimierung, Deduplizierung und Verdichtung) jedes Volumes werden angezeigt. ==== Verbesserung der Blockgeräteerstellung

Workload Factory unterstützt die Erstellung von Blockgeräten aus einem Volume Snapshot.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-block-device.html["Ein Blockgerät aus einem Volume-Snapshot in Workload Factory erstellen"]



==== Workload Tagging für Volumes und Blockgeräte

Workload Factory identifiziert und taggt nun Volumes und Blockgeräte anhand ihrer primären Workload oder Anwendung. Tags können einzelnen Ressourcen zugewiesen oder von verbundenen Speicherressourcen übernommen werden. Dies trägt dazu bei, Speicherkonfigurationen an Workload-Anforderungen auszurichten, Auswirkungen von Vorfällen zu verstehen und die Fehlerbehebung zu erleichtern.

=== EDA-Workloads



==== Erweiterte Latenzanalyse mit synchronisierten Diagrammen für Latenz, IOPS und Durchsatz

Das Panel zur Latenzanalyse enthält nun eine Seite mit *detaillierter Latenzanalyse* und synchronisierten Leistungsdiagrammen:

* *Latenzdiagramm*: Zeigt, wie sich die Latenz im Laufe der Zeit verändert, mit Schwellenwertlinien und Warnmeldungen, wenn Grenzwerte überschritten werden.
* *IOPS Diagramm*: Zeigt die Operationen pro Sekunde, mit Schwellenwertlinien und Indikatoren für vergangene Grenzwertüberschreitungen.
* *Durchsatzdiagramm*: Zeigt Datentransferraten (DataReadBytes oder DataWriteBytes). Wenn im Filter Metadaten ausgewählt sind, zeigt das Durchsatzdiagramm keine Daten.


Alle Diagramme verwenden die gleiche Zeitleiste und zeigen automatisch die korrekten Metriken an, abhängig davon, ob das Ereignis ein Lese- oder Schreibvorgang ist.

Sie können die Ansicht anpassen und Latenzspitzen mit Änderungen der IOPS und des Durchsatzes korrelieren. Markierungen für Grenzwertverletzungen und Details beim Überfahren mit der Maus helfen dabei zu erkennen, wann Schwellenwerte überschritten wurden, und wichtige Kennzahlen für die erkannte Grenzwertverletzung zu überprüfen.

https://docs.netapp.com/us-en/workload-eda/task-analyze-latency-trends.html["Informationen zur Analyse von Latenztrends mit mehreren Diagrammen"^].



==== Häufigkeit der Latenzbenachrichtigung festlegen

Sie können nun auswählen, wie häufig Sie E-Mail-Benachrichtigungen über Latenzüberschreitungen erhalten:

* *Tägliche Erinnerung (Empfohlen)*: Sie erhalten eine Benachrichtigung, wenn ein neues Problem auf einem beliebigen FSx for ONTAP Dateisystem auftritt.


Wenn an einem Tag mehrere Latenzprobleme auf demselben Dateisystem auftreten, erhalten Sie nur eine E-Mail.

Nach dem Senden einer Latenzwarnung für ein Dateisystem wartet Workload Factory 24 Stunden, bevor eine weitere Warnung für dieses Dateisystem gesendet wird.

* *Benachrichtigung bei Latenzüberschreitung (alle 20 Minuten)*: Es erfolgt eine Benachrichtigung, wenn eine Überschreitung festgestellt wird, bis zu einmal alle 20 Minuten.


Tägliche Benachrichtigungen sind standardmäßig aktiviert, um das E-Mail-Aufkommen zu reduzieren und Sie dennoch auf Latenzprobleme aufmerksam zu machen. Die Benachrichtigungseinstellungen lassen sich beim Einrichten der Latenzüberwachung oder beim Bearbeiten der Schwellenwerte ändern.

https://docs.netapp.com/us-en/workload-eda/task-configure-latency-monitoring.html["Erfahren Sie, wie Sie die Latenzüberwachung konfigurieren"^].
